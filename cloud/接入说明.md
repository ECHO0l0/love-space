# 海行多端同步接入

当前代码已加入 Supabase 账号登录、实时订阅、30 秒轮询兜底、断网补传、增量同步和按账号隔离的本机数据库。云项目尚未创建，sync-config.js 留空；生产网站和已安装桌面版尚未更新。

## 免费云项目配置

1. 用户本人登录 https://supabase.com/dashboard ，创建 Free 项目，优先选择靠近使用地区的区域。密码和验证码不通过聊天传递。
2. 在该项目 SQL Editor 执行同目录 `haixing-sync.sql`。不要执行源码根目录的 `setup.sql`，它属于另一个项目。
3. 从项目设置取得 Project URL 与 publishable key（或 legacy anon key），填入源码 `sync-config.js`。不得使用 secret key 或 service_role key。
4. 保留邮箱确认。确认邮件发送能力和实际收件情况需要验证；正式向其他用户开放前检查 Auth 的 SMTP 配置，内置测试邮件能力有限。
5. Auth 的 Site URL 设置为实际网站地址，允许实际网站地址及桌面版 `http://127.0.0.1:8239` 的回调地址。邮箱密码登录不需要 OAuth。
6. 运行 `npm test`、`npm run build`。构建会把 SDK 打包到本机 vendor 文件，浏览器无需访问外部脚本 CDN。
7. 云端权限与实时通道通过真实账号验收后，再部署网站、更新桌面资源并制作新安装包。

## 数据规则

- 数据写入和待上传事件在同一个 IndexedDB 事务中保存，刷新或断网后保留。
- 云端用唯一事件 ID 去重；只接收已登录账号的数据。数据库 RLS 隔离用户，客户端无权直接写表，通过受限 RPC 提交事件。
- 各账号的本机数据库独立，游客记录不自动上传。用户点击“合并本机旧记录”后上传旧数据，游客原记录保留。
- 旧快照的答题次数和每日统计按最大值合并，再加新产生的答题事件。旧快照没有原始事件 ID，无法精确恢复两份快照中的重叠答题，应保留备份。
- 新答题次数按事件增量合并，收藏、笔记按确定的事件顺序合并；自定义方案按方案 ID 合并，删除也记录事件。
- 同一会话的不同题位答案合并。不同会话不混合答案；活动练习入口采用最新修改的会话。当前打开的练习收到远端更新时保留当前操作，不自动跳题。
- 当前版本保存全部同步事件，没有压缩或长期归档策略；用户数和答题量扩大后需要监测容量并实现压缩。

## 本地验证及尚待验证项

- 自动测试覆盖计数合并、重复上传去重、旧数据导入、练习答案合并、收藏取消、方案删除、事务保存和账号隔离。
- `node tests/browser-sync.mjs` 在两个隔离 Chrome 环境中使用模拟云接口验证登录、合并、重复提交、断网补传和退出后隔离，并生成 `test-results/cloud-profile.png`。
- 模拟接口测试不等于真实 Supabase 验收；SQL 执行、邮箱确认、真实 RLS、WebSocket 推送、国内网络和安装后桌面版均待云项目配置后验证。
